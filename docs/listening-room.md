# 视听室

入口：`/listen/`，主导航中的「视听室」。沿用现有 Astro 和 GitHub Pages，无后端和额外运行依赖。

## 日常使用

- 推荐按北京时间（Asia/Shanghai）计算，周一到周五白天推荐科技和产品，19:00 至次日 06:00 推荐生活、写作与人文。
- 周六、周日 08:00–12:00 自动进入「打扫时听」，优先有原生音频的播客，其次是可只听的对谈；其余周末白天进入「周末探索」。可随时手动切换场景，「跟随此刻」恢复自动模式。
- 排序按场景相关度、播放方式和每天轮换的顺序决定。它是明确的内容标签规则，没有后台 AI 请求。
- 小宇宙使用公开节目页提供的原始音频，可倍速、定时暂停、保存位置与续播。浏览器阻止自动播放时，点击原生播放器的播放按钮。
- B 站和 YouTube 按需加载官方 iframe；登录、平台网络、版权和地区限制由原平台决定，可随时「原站打开」。没有下载、搬运或绕过访问限制。
- 卡片上的「＋」加入待播，「✓」标记看完；重复点击恢复。看完会移出队列。仅音频保存具体秒数，视频进度由平台管理。
- 队列和收听状态保存在当前浏览器的 `joez-listening-room-v1` localStorage，不修改 Cubox 或滴答，不跨设备同步。

## 内容与更新

`src/data/media-catalog.json` 是构建时的**收藏快照**。来源为用户的 Cubox 视频/播客标签、直接视频访谈，以及滴答中明确保存的节目链接。正文只保留整理后的公开节目简介，没有原始邮件、任务笔记或账号凭据。重复 URL 合并并保留两个来源。

首版 39 条独立媒体，包含 6 条可直接收听的小宇宙节目。缺少可验证原链的邮件、只有人名或节目名的待办，以及文章形式的访谈，不作为可播放条目收录。部分平台没有公开可靠时长，显示「时长未标注」。

这是静态页面：时间推荐实时切换，来源列表不会在访问页面时自动请求个人账号。后续更新 Cubox：

```bash
npm run media:sync
npm test
npm run build
```

需要本机已安装并登录 `cubox-cli`。凭据由 CLI 自己保管，不写进项目。脚本会保留已有的核实原链、中文简介、音频和时长，并保留滴答收藏；新的视频短链或邮件原链仍需核实补充。

滴答当前通过 Codex 连接器读取。没有给网站配置个人 API 密钥或假设它能访问 Codex 连接器。后续可由 Codex 再次只读读取，导出临时媒体任务 JSON，并执行：

```bash
node scripts/sync-media.mjs --ticktick-file /绝对路径/媒体任务.json
```

输入支持任务数组或 `{ "data": [...] }`，只需要 `id`、`title`、`content`（含节目链接）、`projectId`、`createdTime`、`tags`。不要提交含个人笔记的原始输入文件；生成目录只输出筛选过的媒体字段。

用于补充经核实元数据的可选参数 `--enrichment-file /绝对路径/metadata.json`：

```json
{
  "来源记录ID": {
    "url": "https://www.xiaoyuzhoufm.com/episode/节目ID",
    "title": "核实的节目标题",
    "description": "公开主题的简短中文介绍",
    "audioUrl": "https://公开音频地址",
    "durationMinutes": 60
  }
}
```

`--cubox-file` 和 `--interviews-file` 可使用已读取的 Cubox CLI JSON，避免重复网络请求。默认更新会读取视频/播客标签与访谈搜索。URL 仅接受 HTTPS，去除常见分享参数，内嵌只允许固定的 B 站和 YouTube 域名与合法视频 ID。

## 验证与发布

`npm test` 检查北京时间的切换边界、打扫模式、已看完排除、固定平台播放器 URL、安全链接和媒体目录完整性。`npm run build` 构建全部站点。

推送到 `main` 后，由现有 `Deploy to GitHub Pages` 工作流发布。未修改部署方式。首版另通过真实浏览器验收桌面和手机布局、搜索、来源筛选、队列持久化、音频播放、倍速、定时器、续播以及视频播放器。
